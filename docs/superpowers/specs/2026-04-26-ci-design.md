# ltbase-ts CI Design

## Goal

Add a minimal GitHub Actions CI workflow for `ltbase-ts` that validates the existing static quality gates on every push and pull request.

## Scope

- Add one workflow file at `.github/workflows/ci.yml`
- Run on `push` and `pull_request`
- Use Bun because the repository already targets the Bun runtime
- Execute the existing `bun run check` and `bun test` scripts after a frozen-lockfile install

## Non-Goals

- No token-based E2E coverage
- No secrets-dependent jobs
- No OS or Bun version matrix
- No release, publish, or cache optimization work

## Chosen Approach

Use a single `static` job on `ubuntu-latest` with `actions/checkout` and `oven-sh/setup-bun`. After setup, install dependencies with `bun install --frozen-lockfile`, then run the repository's existing typecheck and test commands.

This keeps the workflow aligned with the current repo surface area and avoids introducing CI-only behavior. The workflow remains easy to understand, and failures map directly to the commands already used locally.

## Alternatives Considered

## Multi-version or multi-OS matrix

Rejected because the current request is only for unit/static coverage, and the repo does not currently advertise cross-platform or cross-version support requirements. A matrix would increase runtime and maintenance cost without a concrete need.

## Add token-based E2E job

Rejected because that requires secrets and external environment coordination. It does not fit the requested static-only scope.

## Verification Plan

Verify locally with the same commands the workflow will run:

```bash
bun install --frozen-lockfile
bun run check
bun test
```
